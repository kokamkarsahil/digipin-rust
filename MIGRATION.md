# Migrating to the unreleased typed API

This checkout keeps package version `0.0.5` while introducing breaking changes
for the next release. Published `0.0.5` documentation and examples use the older
API. No release or publication is part of this change.

## Encode and decode

| Previous API | New API |
| --- | --- |
| `get_digipin(latitude, longitude) -> Result<String, _>` | `encode(latitude, longitude) -> Result<Digipin, _>` |
| `get_coordinates_from_digipin(&str)` | `decode(&str)` |
| Decode a code each time coordinates are needed | Parse a `Digipin` once, then call `center()` or `bounds()` |
| Hyphenated string output | Canonical ten-character uppercase `Display` and `as_str()` |
| Implicitly remove hyphens from input | Explicit migration of stored legacy strings |

The old functions are removed. Update imports and avoid converting typed codes
to owned strings unless your storage or transport requires one:

```rust
use digipin::{decode, encode};

fn main() -> Result<(), digipin::DigipinError> {
    let pin = encode(28.6139, 77.2090)?;
    assert_eq!(pin.as_str(), "39J438TJC7");
    let center = pin.center();
    assert_eq!(decode(pin.as_str())?, center);
    let owned = pin.to_string();
    Ok(())
}
```

`Coordinates` retains its public `latitude` and `longitude` fields.
`Coordinates::new` is a `const` constructor, and `Coordinates::encode` is a
convenience method. Neither constructing nor deserializing `Coordinates`
validates its coverage; validation occurs when encoding.

## Stored codes and human-readable input

Strict parsing accepts exactly ten ASCII characters from `23456789CFJKLMPT`.
Lowercase letters normalize to uppercase. Separators, whitespace, and Unicode
lookalikes are rejected. `decode` uses the same strict parser.

For stored legacy hyphenated codes, deliberately remove only the legacy
separator before parsing:

```rust
use digipin::Digipin;

fn main() -> Result<(), digipin::DigipinError> {
    let legacy = "39J-438-TJC7";
    let canonical = legacy.replace('-', "");
    let pin: Digipin = canonical.parse()?;
    assert_eq!(pin.as_str(), "39J438TJC7");
    Ok(())
}
```

Keep this conversion in an import or migration boundary. Other characters remain
subject to validation. If the database previously stored a DIGIPIN as an object
or used it as a string key, adapt its schema to the canonical string.

The official human-readable grouping is now **3–4–3 with spaces**:

```rust
use digipin::Digipin;

fn main() -> Result<(), digipin::DigipinError> {
    let pin = Digipin::parse_display("39J 438T JC7")?;
    assert_eq!(pin.as_str(), "39J438TJC7");
    assert_eq!(pin.display_grouped().to_string(), "39J 438T JC7");
    Ok(())
}
```

`parse_display` accepts either raw ten-character input or exactly `XXX XXXX XXX`.
It does not trim or collapse whitespace. `display_grouped` returns a formatting
adapter and does not allocate unless the caller requests a `String`.

## Coverage, precision, and errors

Encoding rejects NaN, infinity, latitude outside `2.5..=38.5`, and longitude
outside `63.5..=99.5`. These are coverage-rectangle checks, not political-border
checks. Review exhaustive error matches against the new `DigipinError` API.

Shared grid edges now follow the May 2026 technical document: the north or east
cell owns a coordinate exactly on an interior edge. A code generated by the old
implementation at an exact edge can therefore change when re-encoded. Existing
codes remain valid and identify their original cells.

Decoding returns the cell center, not the original coordinate. Each cell spans
`0.000034332275390625°` on each axis. Replace broad approximate round-trip checks
with `pin.bounds().contains(original)` and `pin.center().encode() == Ok(pin)`.
Bounds include south and west edges and exclude north and east edges, except at
the maximum outer coverage boundaries.

## Serde and platform support

With `serde`, a `Digipin` serializes as a canonical string and validates during
deserialization. Lowercase input normalizes; legacy hyphenated strings and
grouped display strings must be converted explicitly before deserialization.
`Coordinates` keeps the object shape `{"latitude": ..., "longitude": ...}`.

The library now supports `no_std` by default, including its optional Serde
support, and does not require an allocator. The minimum supported Rust version
is **1.85**, with edition **2024**.
